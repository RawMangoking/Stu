## 1. Project Overview

This project improves a Java-based Course Registration application using Git, Maven, JUnit 5, Jenkins Declarative Pipeline, Docker, and Kubernetes with Minikube.

The work includes:

- Refactoring the application into a multi-module Maven project.
- Fixing the course registration capacity boundary defect.
- Implementing course withdrawal while maintaining consistent student and course state.
- Automating build, test, and packaging workflows using a Jenkins Declarative Pipeline.
- Deploying Nginx on Kubernetes and demonstrating scaling and self-healing.

## 6. Registration Capacity Boundary Defect

The original registration capacity validation used a strict greater-than comparison. This incorrectly allowed an attempted registration when the course was already full.

The condition was corrected to reject registration when the current enrollment is greater than or equal to the course capacity.

### Verification

JUnit tests verify that:

- Registration is rejected when the course is already full.
- Registration succeeds when exactly one seat remains.
- A rejected registration does not change the student's registration state.
- A rejected registration does not change the student's total credits.
- A rejected registration does not change the course enrollment count.

The existing tests were retained, and additional tests cover the boundary conditions.

## 7. Course Withdrawal — Question Set E

The assigned change request was to implement a withdrawal operation that allows a student to withdraw from a course in which they are registered.

### 7.1 Implementation

The withdrawal operation:

1. Checks whether the student is registered in the course.
2. Removes the course from the student's registrations.
3. Subtracts the course credits from the student's total.
4. Decreases the course's current enrollment by one.
5. Rejects withdrawal safely if the student is not registered in the course.

The course enrollment decrement operation prevents the enrollment count from becoming negative.

### 7.2 Test Coverage

JUnit tests cover:

- Successful course withdrawal.
- Removal of the course from the student's registration set.
- Correct subtraction of course credits.
- Correct reduction in course enrollment.
- Safe handling of withdrawal from a course in which the student is not registered.
- Preservation of state after an unsuccessful withdrawal.
- Registration by another student using the seat released by withdrawal.
- Protection against negative enrollment counts.

The withdrawal implementation maintains consistent state across the `Student` and `Course` objects.

- Jenkins job: `Student-Starter-CI`

- Execution environment: Linux-based Jenkins Docker container.
- Build executor: Jenkins built-in node.
- Maven: Configured through Jenkins' tool configuration.

The pipeline uses Linux-compatible `sh` commands and `agent any`.

### 8.2 Pipeline Stages

The pipeline contains the following stages:

1. **Checkout:** Retrieves the repository from GitHub.
2. **Build and Test:** Runs `mvn clean test` from the repository root.
3. **JUnit Results:** Publishes the Surefire XML reports.
4. **Package:** Runs `mvn package` after the build-and-test stage succeeds.
5. **Artifact Archiving:** Archives the packaged JAR when the pipeline completes successfully.

### 9.5 Self-Healing

Use the actual Pod name returned by `kubectl get pods`:

```powershell

kubectl get pods -w
```

Kubernetes created a replacement Pod, restoring the desired replica count of three.

The final verification showed:

- Three desired and available replicas.
- Three running Pods.
- A NodePort Service exposing Nginx.

The Deployment controller continuously reconciles the actual cluster state with the desired state specified in the Deployment. When a Pod is deleted, the controller creates a replacement to maintain the desired replica count.
